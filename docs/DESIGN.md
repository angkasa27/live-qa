# Sual: interface design

Companion to [REQUIREMENTS.md](REQUIREMENTS.md), which deliberately records no interface decision.
This is where they stop being open. Same bar: each entry states a decision and what makes it
load-bearing, so changing one is an argued decision rather than drift.

Drift is the specific failure this document exists to prevent. Before it was written the primary
button existed as five near-identical class strings that disagreed about radius, height, weight,
transition and focus ring — nothing broken, but every new screen picked one at random.

## The rule everything else follows

**Content is flat and full width. Controls are rounded.**

Nothing gets a card for existing. A list of sessions, a question, an answer, a person — all of it
runs the full width of the column, separated by hairlines, with no border of its own. The moment
something has a radius, it is tappable.

This is what the whole interface is arranged around, and it is worth stating first because the
previous design did the opposite: every session, every question and every answer sat in its own
bordered card, three deep in places, so a border meant nothing and buttons did not read as
buttons. If you are adding a box, you are either adding a control or you are wrong.

Four things carry a radius while sitting still, and they are the whole exception list: the
promoted running-session card on the jamaah home, an `Alert`, the question cards on the admin
board, and the countdown. Each is a thing set apart from the content around it, not content.

## Stack

| Piece | Choice |
|---|---|
| CSS | Tailwind v4, tokens declared in `app/globals.css` under `@theme inline` |
| Components | shadcn, `base-vega` style, configured in `components.json` |
| Primitives | `@base-ui/react` — what `base-vega` builds on, not Radix |
| Variants | `class-variance-authority`, merged through `cn` in `lib/utils.ts` |
| Icons | `lucide-react` |

Three places components live, and the difference matters:

- `components/ui/` — shadcn-owned. Generated by `shadcn add`, then edited to the house rules
  below. Regenerating one **discards those edits**; re-apply them from that file's own header
  comment, which lists them.
- `components/` — composed app pieces that know about Sual's domain.
- `components/admin/` — admin-only. No public route imports from here.

## Tokens

Declared once in `app/globals.css`. Written in oklch; each carries the sRGB it was converted from
as a trailing comment, so the shadcn rename stays checkable against git history.

original design's.

| `--popover` | `#ffffff` | The `Modal` surface. |
| `--primary` | `#16624f` | The single green. Anything actionable, and nothing else. |
| `--primary-foreground` | `#ffffff` | On green. |
| `--secondary` | `#ffffff` | A bordered button standing on paper. |

| `--muted-foreground` | `#77716a` | Second text tier: labels, metadata, hints. |
| `--accent` | `#eef4f1` | Green-tinted surface. An info alert, a recording badge. |

The trap this palette walked into once: **shadcn's `--accent` and `--muted` are surface colours;

both and left 130-odd class usages rendering near-white on near-white. If a future `init` or a
base-colour change runs, check these two first.

### Adding a colour

oklch makes the palette's structure visible, and that structure is the rule:

- every neutral — paper, ink, both borders, both muted tiers, the bar greys — sits at **hue 78–87**
- every green sits at **hue 165–172**
- both reds sit at **hue 28–30**

A new colour holds one of those hues and moves L and C. Never eyeball a hex. The converter used
for the current set round-trips the existing tokens exactly, so verify a new value by converting
a known token and checking it matches the table.

### Light only

There is no `.dark` block and no dark-mode variant, on purpose. The dark surfaces in the product
are *places*, not a colour scheme the phone gets to pick, and there are two:

- **The admin bar** — `Toolbar variant="ink"`. Fully tokenised now (`--foreground` ground,
  `--bar-line`, `--on-bar`, `--on-bar-2`), so it is dark without being a dark theme. It is ink so
  an operator mid-majelis is never unsure which side of the product they are typing into.
- **`SpeakerDeck`** — the only remaining literal-hex zone, plus the `Poster` gradient. A hall
  reads it from ten metres with the lights up, so its ground is darker than the admin bar and its
  type is clamped against the viewport rather than stepped on the product ramp. Bringing it into
  the token set means designing a dark ramp first; until someone needs one, one literal-hex zone
  is cheaper than a second palette.

There are also no `--chart-*` or `--sidebar-*` tokens: nothing charts, nothing has a sidebar.

## Type

**One face.** `Public Sans`, wired in `app/layout.tsx` as `--font-sans-ui` → `font-sans`, weights
400–800. Weight and size carry what a second face used to; there is no serif and no mono anywhere
in the product.

The earlier three-face scheme (Plus Jakarta Sans, Newsreader for reading matter, IBM Plex Mono for
small-caps labels) is gone. The serif argument — that a question and a scholar's answer are text
to be *read* rather than interface chrome — is now made with size and weight instead: a question
is `text-lg` semibold, its metadata `text-xs` faint.

**One ramp**, `--text-2xs` through `--text-3xl`, declared in `globals.css` with what each step
carries. Read it there; it is not repeated here, because a second copy can only drift. Three
things about it are not in that file:

- It keeps Tailwind's names but not Tailwind's values. **`text-sm` is 12.5px here, not 14**, which
  surprises anyone arriving from stock Tailwind — and is the point. There is one ramp.
- Every step is scaled by a single `--step`, so the whole product resizes from one number if a
  size control is ever wired up. Nothing wires one up today.
- Reach for a neighbour before adding an arbitrary size. `SpeakerDeck` is the one exemption and
  clamps against the viewport instead.
- **Every step carries its own line-height and letter-spacing**, so neither is ever a call-site
  decision. Set the size; the rest comes with it. Tracking tightens as the type grows — the
  ordinary optical correction — and there is none below 14.5px:

  | | `2xs`–`md` | `lg` | `xl` | `2xl` | `3xl` |
  |---|---|---|---|---|---|
  | tracking | none | −0.01em | −0.02em | −0.025em | −0.03em |

  Three overrides exist in the whole product and each says why where it sits: an answer body
  (`leading-[1.65]`, the longest prose here), an uppercase eyebrow (`tracking-[0.12em]`, because
  uppercase needs positive spacing), and `SpeakerDeck`, which is off this ramp entirely.
  Reaching for `leading-snug` or `tracking-[-0.02em]` per element is how nine sizes became
  nineteen leadings and six trackings, all of them slightly wrong. If a size needs different
  leading everywhere, change the ramp, not the element.

### Weight

Four weights, and each has one job. `font-medium` was retired: it was the weight nobody chose
deliberately, and it was what made three admin field labels lighter than every other field
label, and `AlertTitle` / `EmptyTitle` / `DrawerTitle` lighter than every other title.

| Weight | Class | Carries |
|---|---|---|
| 800 | `font-extrabold` | Page headings (`text-3xl`), the countdown digits, an avatar initial. Nothing else. |
| 700 | `font-bold` | Every other heading and title, form labels, badges, buttons, section rules. The default for anything that is not prose. |
| 600 | `font-semibold` | A question. It is the thing being read, and this is the only place it is used. |
| 400 | `font-normal` | Prose and metadata — and de-emphasising a fragment inside a bolder parent, like `(opsional)` after a label. |

### Where the design is not the standard

The design files are a drawing, not a system, and they waver in places. Where they do, this
document picks one value and the code follows it — matching the drawing exactly would import
the drift:

| The design draws | We ship |
|---|---|
| A word-badge at 30px in a bar, 30px in a session row, 28px on a person | One badge height, 30px |
| An edge on row badges, none on bar badges | Always an edge, matching the tone — invisible on `live` anyway |
| Section headings at 15px, row titles at 15.5px | One step, `text-xl` |
| Chips at 40px, except the refresh chip at 38px | One chip size, 40px |
| Field padding at 13px, 14px and 15px | 14px |

None of these is visible as a difference; all of them are visible as inconsistency once you
have four screens open. When a new screen disagrees with this table, the table wins.

## Shape

Three radii — `rounded-sm` 10px, `rounded-md` 14px, `rounded-lg` 20px — declared in `globals.css`
with what each is for, plus `rounded-full` for pills, badges, toggles and icon buttons.

`rounded-xl` and above are deliberately **not defined**. They would fall through to Tailwind's
defaults, so they must not appear; a grep for them should come back empty. If something seems to
need a fourth radius, re-read the rule at the top of this document — it probably needs to be flat.

## Touch targets

**This is the rule that overrides shadcn's defaults, and the one most likely to be lost on a
regenerate.** shadcn ships buttons at `h-8`/`h-9`/`h-10` — 32/36/40px. All three are below the
44px minimum.

`REQUIREMENTS.md` puts the jamaah on "a mosque floor in the evening, phone, one hand", in a 10–30
minute Q&A window. A 36px target is a design failure in that room, not a density preference.

| Step | Height | For |
|---|---|---|
| `sm` | 42px | Dense admin rows — the actions inside a question card |
| `md` | 48px | The default, and the design's `--tap` |
| `lg` | 54px | Full-width, the sticky call to action at the foot of a screen |
| `chip` | 40px | A pill that behaves as a control: answer timestamps, the list refresh |
| `icon` | 48px | Square, in a bar |

Nothing in the button scale is under 40px. Non-interactive pills and badges may be smaller;
`Badge` is never tappable, and anything a thumb lands on is a `Button` — `size="chip"` is the pill
that looks like a badge and behaves like a control.

## Focus and motion

Every interactive element carries a visible focus ring — no exceptions, and this is not negotiable
per-component. Several hand-rolled buttons shipped without one, which is part of why the shared
component exists.

The ring is **3px, green, offset 2px**, set as a base rule in `globals.css` and repeated in each
component's `focus-visible:` classes. Both are needed: the base rule is the floor for anything
that sets none of its own, and a component's own utilities win over it, so a component that sets a
ring must set this one.

`globals.css` keeps two rules that have no shadcn equivalent:

- `input, textarea, select { font-size: max(1rem, 16px) }` — iOS zooms any focused input under
  16px, which throws a one-handed user out of the form. Any Input or Textarea adopted from shadcn
  must not undercut this.
- A `prefers-reduced-motion` block that stops animation. `Spinner` depends on it: under reduced
  motion it stops spinning, and the busy label ("Menyimpan…") carries the meaning alone. Never
  make a spinner the only signal that something is happening.

## Two traps that cost real bugs

Both bit during the redesign, both are invisible until something renders wrong, and neither is
confessed by any config file.

- **`w-full` plus a horizontal margin overflows the viewport.** `w-full` is 100% of the *parent*,
  so `mx-5` on a `w-full` box puts its right edge 20px past the screen. `Alert` and `Empty` both
  shipped with `w-full` and both overflowed the moment a call site gave them a margin. Neither
  sets it now: a block or grid box at `width: auto` already fills its container minus margins,
  which is what the flat layout wants. Do not add `w-full` to anything a caller might margin.
- **A `Button` rendered as a link loses button semantics.** Base UI needs to be told when `render`
  hands it something that is not a native `<button>`, or it silently drops the role and keyboard
  handling and warns in the console. `components/ui/button.tsx` defaults `nativeButton` from
  whether `render` was passed, so `render={<Link/>}` is correct by default; a `render` that really
  is a native button passes `nativeButton` itself.

## Component inventory

### Variant vocabulary

Variant names say what a thing **means**, never what colour it is, and the same word means the
same thing across every component that has it. This is what makes a screen readable without
looking up each component:

`default` · `outline` · `ghost` · `live` · `warning` · `accent` · `muted` · `destructive` · `info`

Sizes are `sm` / `md` / `lg` / `icon`, plus `chip` on `Button` and `count` on `Badge`. Adding a
variant means adding a meaning; if the meaning already exists under another name, use that name.

### Installed, with house rules

Every file in `components/ui/` carries a header comment listing its edits. `shadcn add`
overwrites them; that comment is what to re-apply from.

| Component | House rules applied |
|---|---|
| `button` | Sizes rewritten to the scale above. Six variants: `default` filled, `outline` bordered on card, `ghost` text-only, `destructive`, `warning`, `link`. `destructive` is outlined, not filled — the system is append-only, so nothing is irreversible enough to earn a solid red block; for the lighter destructive act, use `ghost` with `text-destructive`. Defaults `nativeButton` from `render`. |
| `badge` | Colour and shape split onto two axes so the design's pills are not a variant each: `variant` is the meaning, `size` is `default` or `count`. Uppercase dropped — the design sets these in sentence case, and Indonesian labels are long enough already. A badge states; it is never tappable. |
| `alert` | Four tones with fixed meanings: `default` neutral, `info` how the page works, `warning` waiting on a human, `destructive` a failure. |
| `item` | The flat row: `row` (hairline top, full width, no radius) is the default, `boxed` is the exception for a row that is itself a control. Media variants `image` (96px at 16:9) and `avatar`. |
| `toolbar` | The one bar. `paper` for the jamaah, `ink` for the admin, with `ToolbarBack` / `ToolbarTitle` / `ToolbarSpacer`. |
| `toggle` | States what it currently **is** and changes words when tapped — pass both labels as `ToggleOn` / `ToggleOff`. A toggle that only highlights is one whose meaning you have to remember. |
| `collapsible` | Carries the admin board's section header: marker icon, name, count, chevron. Note that Base UI writes `data-panel-open` only while open and never `="false"`, so the closed state must be the CSS default. |
| `checkbox` | 22px, up from shadcn's 16 — both places it appears are one-handed on a phone. |
| `avatar` | Cut to the one shape used: a 38px disc holding an initial. Regenerating restores `AvatarGroup`, `AvatarBadge` and size variants, none of which have anywhere to go. |
| `input` | 48px, 1.5px border — at this size a hairline reads as a disabled field. Outline focus, no shadow, no dark branches. |
| `textarea` | Same, plus a green halo on focus: the question box is the thing on the page you are meant to be typing into, and usually the only one. |
| `field` | Labels at `text-md` bold with a faint 15px icon; help text and errors at `text-xs`. |
| `empty` | No `w-full` (see traps above). Flat bands, not cards. |
| `drawer` | Header left-aligned rather than centred. |
| `switch` | 32x18px → 44x24 with a 20px thumb. |
| `alert-dialog` | Backs `admin/Confirm`. |
| `separator`, `label` | Near-stock. |

A button-styled `<Link>` uses `<Button render={<Link href=… />}>`. Do not reach for a polymorphic
`as` prop or `Slot`.

### Keep, do not replace

| Component | Why |
|---|---|
| `admin/Modal.tsx` | Built on native `<dialog>`, which already gives inertness, focus containment, Escape, and focus return. A dialog library would add a dependency to re-implement what the platform ships. |
| `Spinner.tsx` | Ten lines, and coupled to the reduced-motion rule above. |
| `MetaList.tsx` | The icon-led facts under a title, on every screen in both design files. The pictogram carries what a label used to say, which only works if the same icon means the same fact everywhere: `User` speaker, `MapPin` venue, `Clock` time, `MessageCircle` questions. |
| `PageShell.tsx` | `<main>` plus the sticky action. The action is a *sibling* of `<main>`, not its last child: inside the scroll container `sticky bottom-0` only pins once content overflows, so on a short list the bar sat under the content instead of under the thumb. |
| `Player.tsx`, `SpeakerDeck.tsx`, `Poster.tsx` | No generic equivalent exists. |

### Domain-shaped, and why they cannot be generic

These encode rules from `REQUIREMENTS.md`. A generic component would let a caller violate one.

- **The bar tag on a majelis** — `Badge size="bar"` in the detail page's `Toolbar`. It answers
  "what will I find here", not "what lifecycle state is this in", which is why a scheduled
  session shows nothing, a running one shows *Berlangsung*, and an archive shows *Rekaman*
  rather than *Arsip*. An archive with no recording shows nothing at all: the tag names what is
  on the page, so it must not claim a recording that is not there.

  This is why the old `StatusBadge` is gone. It rendered the `scheduled`/`live`/`archived`
  triple and was careful to say nothing about video — state ⊥ video being an orthogonal pair —
  but the screen never wanted the lifecycle state. `live` remains the only user of `--live`.
- **`QuestionItem`'s pending treatment** — warn ground, "Menunggu review admin", and "hanya Anda
  yang melihat ini". Straight out of the visibility matrix: a pending question is visible to its
  asker and to nobody else. The reassurance is load-bearing, not decoration; without it people
  submit twice.
- **`AnswerBlock`** — one green rule down the left edge and the speaker's name, nothing more. It
  shows *that* a revision happened, never the prior wording; full history is an admin capability.
  The speaker is credited through `speakerShort()` so a long nasab does not bury the word
  "menjawab".
- **The replay chip** — carries a position into the recording and seeks in place when a player is
  on the page. It marks where the *answer* starts, not where the question is read out.
- **`admin/SessionControls`** — the two controls that change mid-majelis are the only two on the
  board, and where a session goes next is one button naming what happens. A three-way status
  picker asks the operator to hold a state machine in their head and offers two wrong answers
  beside the right one.

## What we do not install

Each `shadcn add` is a decision. Not installed, and not to be added without one:

Dark mode · charts · sidebar · a dialog library · a date picker · toast · `toggle-group` ·
`tooltip` · `select`.

`toggle` **is** installed, as the self-describing deck control; `toggle-group` still is not,
because nothing groups them.

Anything serving a feature listed under `REQUIREMENTS.md` § *Out of scope* is out of scope here
too — no vote control, no reply thread, no search input.
