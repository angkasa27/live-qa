# Sual: interface design

Companion to [REQUIREMENTS.md](REQUIREMENTS.md), which deliberately records no interface decision.
This is where they stop being open. Same bar: each entry states a decision and what makes it
load-bearing, so changing one is an argued decision rather than drift.

Drift is the specific failure this document exists to prevent. Before it was written the primary
button existed as five near-identical class strings that disagreed about radius, height, weight,
transition and focus ring — nothing broken, but every new screen picked one at random.

## Stack

| Piece | Choice |
|---|---|
| CSS | Tailwind v4, tokens declared in `app/globals.css` under `@theme inline` |
| Components | shadcn, `base-vega` style, configured in `components.json` |
| Primitives | `@base-ui/react` — what `base-vega` builds on, not Radix |
| Variants | `class-variance-authority`, merged through `cn` in `lib/utils.ts` |
| Icons | `lucide-react` |

Three places components live, and the difference matters:

- `components/ui/` — shadcn-owned. Generated by `shadcn add`, then edited to the house rules
  below. Regenerating one **discards those edits**; re-apply them from this document.
- `components/` — composed app pieces that know about Sual's domain.
- `components/admin/` — admin-only. No public route imports from here.

## Tokens

Declared once in `app/globals.css`. Written in oklch; each carries the sRGB it was converted from
as a trailing comment, so the shadcn rename stays checkable against git history.

### shadcn's vocabulary, carrying Sual's palette

The names are shadcn's so that a pulled-in component works unmodified. The values are the
original design's.

| Token | Value | Means |
|---|---|---|
| `--background` | `#faf9f7` | Warm paper. The ground of every public screen. |
| `--foreground` | `#1c1a17` | Ink. |
| `--card` | `#ffffff` | A surface lifted off the paper: question cards, form panels, headers. |
| `--popover` | `#ffffff` | The `Modal` surface. |
| `--primary` | `#16624f` | The single green. Anything actionable, and nothing else. |
| `--primary-foreground` | `#ffffff` | On green. |
| `--secondary` | `#ffffff` | A bordered button standing on paper. |
| `--muted` | `#f4f2ed` | A *sunk* surface — the tab bar, a hover ground. Never text. |
| `--muted-foreground` | `#77716a` | Second text tier: labels, metadata, hints. |
| `--accent` | `#eef4f1` | Green-tinted surface. The answer block, the count pill. |
| `--accent-foreground` | `#16624f` | Green text sitting on that tint. |
| `--destructive` | `#a13124` | Errors and destructive actions. |
| `--border` | `#e2ded6` | The standard hairline. |
| `--ring` | `#16624f` | Focus rings are green here, not neutral. |

The trap this palette walked into once: **shadcn's `--accent` and `--muted` are surface colours;
an earlier version of this codebase used those names for text colours.** `shadcn init` overwrote
both and left 130-odd class usages rendering near-white on near-white. If a future `init` or a
base-colour change runs, check these two first.

### Sual-only

shadcn has no word for these, and each carries a meaning the interface may not spend elsewhere.

| Token | Value | Means |
|---|---|---|
| `--live` | `#b2382a` | A running session. **Only** that — never an error, never a warning. |
| `--warn` | `#8a5a12` | Waiting on a human. Text on `--warn-soft`. |
| `--warn-soft` | `#fdf8ee` | The ground of a pending question. |
| `--warn-border` | `#d9c9a8` | Its edge. |
| `--warn-pill` | `#f3e4c6` | The "Menunggu review" badge. |
| `--border-soft` | `#ece8e1` | A quieter hairline: tab bar, sticky headers. |
| `--faint` | `#8b857c` | Third text tier, below `--muted-foreground`. Timestamps, attribution. |
| `--accent-border` | `#bcd6cc` | Edge of a green-tinted surface. |
| `--destructive-soft` | `#fdf1ef` | Error panel ground. |
| `--destructive-border` | `#c9857c` | Its edge, and the danger-zone panel in the edit form. |

Three text tiers — `--foreground`, `--muted-foreground`, `--faint` — is the whole set. A fourth
would be indistinguishable in a mosque at night.

### Adding a colour

oklch makes the palette's structure visible, and that structure is the rule:

- every neutral — paper, ink, both borders, both muted tiers — sits at **hue 78–85**
- every green sits at **hue 165–172**
- both reds sit at **hue 28–30**

A new colour holds one of those hues and moves L and C. Never eyeball a hex. Verify a conversion
by building and reading the sRGB fallback Tailwind emits alongside the oklch — it should match the
value in the table above.

### Light only

There is no `.dark` block and no dark-mode variant, on purpose. The two dark surfaces in the
product — the `AdminShell` ink header and `SpeakerDeck` — are painted explicitly, because they are
*places*, not a colour scheme the phone gets to pick. They use literal hexes (`#35302a`, `#a8a096`,
`#e8e5df`, `#f7f4ed`) that sit outside the token set deliberately. Bringing them in means
designing a dark ramp first; until someone needs one, two literal-hex zones are cheaper than a
second palette. There are also no `--chart-*` or `--sidebar-*` tokens: nothing charts, nothing has
a sidebar.

## Type

Three faces, wired in `app/layout.tsx`, each with a job:

| Face | Variable | Carries |
|---|---|---|
| Plus Jakarta Sans | `--font-sans-ui` → `font-sans` | Interface. The default. |
| Newsreader | `--font-serif-reading` → `font-serif` | Questions and answers — the reading matter. |
| IBM Plex Mono | `--font-mono-label` → `font-mono` | Small caps labels: the `JAWABAN` eyebrow, timecodes. |

The serif is the product's one typographic argument: a question a student wrote, and a scholar's
answer, are text to be *read*, not interface chrome. Only `QuestionCard`'s body, `AnswerBlock`, and
page titles take it.

**Size scale.** The design uses an odd-pixel scale that Tailwind's even-numbered defaults do not
contain, so both are in play. The full set actually in use:

| px | Class | Used for |
|---|---|---|
| 10 | `text-[0.625rem]` | The mono `JAWABAN` eyebrow |
| 11 | `text-[0.6875rem]` | Status badges |
| 12 | `text-xs` | Metadata, hints |
| 13 | `text-[0.8125rem]` | Dense secondary copy |
| 14 | `text-sm` | The workhorse |
| 15 | `text-[0.9375rem]` | Comfortable body |
| 16 | `text-base` | Form controls (also the iOS floor, below) |
| 17 | `text-[1.0625rem]` | Question body, serif |
| 18–19 | `text-lg`, `text-[1.1875rem]` | Card titles |
| 23–30 | `text-[1.4375rem]`, `text-2xl`, `text-[1.625rem]`, `text-3xl` | Page titles |

That is the allowed set. Adding a new arbitrary size needs a reason; reach for a neighbour first.

## Shape

`--radius: 0.625rem`, which derives the scale shadcn's `@theme` block computes from it:

| Class | px | Used for |
|---|---|---|
| `rounded-md` | 8 | Small controls |
| `rounded-lg` | 10 | Buttons, inputs, admin rows |
| `rounded-xl` | 14 | Panels, cards, the primary CTA |
| `rounded-2xl` | 18 | Event cards, question cards |
| `rounded-full` | — | Pills and badges |

`0.625rem` was chosen so `rounded-xl` lands on exactly 14px, which is the value ten call sites had
already hard-coded as `rounded-[14px]`. Those become `rounded-xl`; no new arbitrary radii.

## Touch targets

**This is the rule that overrides shadcn's defaults, and the one most likely to be lost on a
regenerate.** shadcn ships buttons at `h-8`/`h-9`/`h-10` — 32/36/40px. All three are below the
44px minimum.

`REQUIREMENTS.md` puts the jamaah on "a mosque floor in the evening, phone, one hand", in a 10–30
minute Q&A window. A 36px target is a design failure in that room, not a density preference.

| Step | Height | For |
|---|---|---|
| `sm` | 36px | Dense admin rows only, never a public surface |
| `md` | 44px | The default. Every attendee-facing control. |
| `lg` | 48px | Primary CTA |
| `xl` | 52px | The full-width "Ajukan pertanyaan" bar |

Pills and badges below 36px (`min-h-[1.75rem]`, `min-h-[1.875rem]`) are fine **only when not
interactive**. The one exception is `QuestionCard`'s replay pill, which is a small target beside a
large one; if it ever becomes the only way to reach the recording, it grows.

**Known gap:** `AdminBoard` and `admin/Segmented` currently use 36–40px targets on surfaces
`REQUIREMENTS.md` A3 says must be "operable on a phone as well as a laptop". Not fixed here;
fix it when those files are migrated.

## Focus and motion

Every interactive element carries a visible focus ring — no exceptions, and this is not negotiable
per-component. Several hand-rolled buttons shipped without one, which is part of why the shared
component exists.

`globals.css` keeps two rules that have no shadcn equivalent:

- `input, textarea, select { font-size: max(1rem, 16px) }` — iOS zooms any focused input under
  16px, which throws a one-handed user out of the form. Any Input or Textarea adopted from shadcn
  must not undercut this.
- A `prefers-reduced-motion` block that stops animation. `Spinner` depends on it: under reduced
  motion it stops spinning, and the busy label ("Menyimpan…") carries the meaning alone. Never
  make a spinner the only signal that something is happening.

## Component inventory

### Installed, with house rules

Every file in `components/ui/` carries a header comment listing its edits. `shadcn add`
overwrites them; that comment is what to re-apply from.

| Component | House rules applied |
|---|---|
| `button` | Sizes rewritten to the 44px scale (`sm` 36 / `md` 44 / `lg` 48 / `xl` 52 / `icon` 44). Variants trimmed to `default`, `outline`, `ghost`, `destructive`, `link`; `secondary`, `xs`, `icon-xs`, `icon-sm` dropped. `destructive` is outlined, not filled — the system is append-only, so nothing is irreversible enough to earn a solid red block. |
| `input` | `h-9` (36px) → `min-h-11`. `md:text-sm` dropped — it read as if the iOS zoom guard could be undercut here. Outline focus, no shadow, no dark branches. |
| `textarea` | Same edits as `input`. Default stays sans; `SubmitForm` passes `font-serif` for the question box. |
| `field` | Unmodified. `components/admin/Field.tsx` is now a thin wrapper over it, keeping the `label`/`id`/`hint` API its ten call sites use. |
| `label` | Unmodified. |
| `alert` | Three tones with fixed meanings: `default` neutral, `warn` waiting on a human, `destructive` a failure. The generated `destructive` was a plain card; it now carries the soft ground and coloured edge. |
| `badge` | Added `live` (the only user of `--live`), `warn`, `accent`. Dropped `secondary`, `ghost`, `link`. Fixed `h-5` → `min-h-5.5` so Indonesian labels don't clip. |
| `empty` | The generated base set `border-dashed` with no width or colour, so no border drew. Fixed, and `rounded-lg` → `rounded-xl`. |
| `drawer` | Header left-aligned rather than centred: the session sheet puts a title and a close action on one row. |
| `switch` | 32x18px → 44x24 with a 20px thumb. The generated size is a pointer control, and these sit in the session sheet the admin works with a thumb. No shadow, no dark branches. |
| `separator` | Arrived as a transitive dependency of `field`. Unmodified, unused directly. |

A button-styled `<Link>` uses `buttonVariants({ variant, size })` as its `className`. There are
about ten. Do not reach for a polymorphic `as` prop or `Slot` to avoid this.

### Keep, do not replace

| Component | Why |
|---|---|
| `admin/Modal.tsx` | Built on native `<dialog>`, which already gives inertness, focus containment, Escape, and focus return. A dialog library would add a dependency to re-implement what the platform ships. |
| `Spinner.tsx` | Ten lines, and coupled to the reduced-motion rule above. |
| `admin/Segmented.tsx` | 32 lines against 134 for `toggle` + `toggle-group`, and the generated pair marks selection with `bg-muted` rather than the green fill, sizes at 32–40px, and `w-fit` rather than the equal-width fill a phone needs. Three overrides in two regenerable files to land back where Segmented already is. |
| `StatusBadge.tsx` | Domain-shaped — see below. Now a thin wrapper over `Badge`. |
| `Player.tsx`, `SpeakerDeck.tsx` | No generic equivalent exists. |

### Domain-shaped, and why they cannot be generic

These encode rules from `REQUIREMENTS.md`. A generic component would let a caller violate one.

- **`StatusBadge`** — the `scheduled`/`live`/`archived` triple, with `live` the only user of
  `--live`. It says nothing about whether the session has video: state ⊥ video is an explicit
  orthogonal pair, and a badge that merged them would be the exact modelling error the
  requirements warn about.
- **`QuestionCard`'s pending treatment** — warn surface, "Menunggu review", and "hanya Anda yang
  melihat ini". Straight out of the visibility matrix: a pending question is visible to its asker
  and to nobody else. The reassurance is load-bearing, not decoration; without it people submit
  twice.
- **`AnswerBlock`'s revised marker** — the public sees *that* a revision happened, never the prior
  wording. Full history is an admin capability.
- **The replay pill** — carries a position into the recording, and seeks in place when a player is
  on the page. It marks where the *answer* starts, not where the question is read out.

## What we do not install

Each `shadcn add` is a decision. Not installed, and not to be added without one:

Dark mode · charts · sidebar · a dialog library · a date picker · toast · `toggle-group`.

Anything serving a feature listed under `REQUIREMENTS.md` § *Out of scope* is out of scope here
too — no vote control, no reply thread, no search input.
